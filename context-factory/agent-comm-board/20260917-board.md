#### `src/utils/share-to-instagram.ts`
Platform-aware share helper.

```ts
import Share from 'react-native-share';
import { Platform } from 'react-native';

export async function canShareToInstagram(): Promise<boolean>
export async function shareToInstagramStories(localUri: string): Promise<void>
```

**`canShareToInstagram`:**
- Android: `Share.isPackageInstalled('com.instagram.android')`
- iOS: use `Linking.canOpenURL('instagram-stories://share')` (requires URL scheme registration in `app.json`)

**`shareToInstagramStories`:**
```ts
await Share.shareSingle({
  backgroundImage: localUri,   // must be a file:// path, not a URL
  social: Share.Social.INSTAGRAM_STORIES,
  appId: process.env.EXPO_PUBLIC_FB_APP_ID ?? '',
});
```

The `localUri` must be a `file://` path. If the photo is remote-only (not yet cached), download it first using `downloadPhotoToCache` from `src/lib/photo-files.native.ts`.

#### `src/utils/share-to-instagram.web.ts`

### Changes to existing files

#### `src/components/photo-grid.tsx` — add `onDetailPress`

Add an optional `onDetailPress?: () => void` to `GridItem` type and `PhotoCell` props. This fires when the cell is tapped **outside** selection mode, navigating to the detail view. Keep `onPress` for selection-mode taps only.

> **Important:** `onFailedPress` takes priority over `onDetailPress` when `syncStatus === 'failed'`. Failed cells still show the retry alert, not the detail view.

```ts
// Updated GridItem type
export type GridItem = {
  key: string;
  source: string;
  syncStatus: SyncStatus;
  isPicked?: boolean;
  isSelected?: boolean;
  onPress?: () => void;          // selection-mode tap
  onDetailPress?: () => void;    // outside selection mode → detail view
  onFailedPress?: () => void;    // failed cell tap → retry alert
};
```

Update `PhotoCell.handlePress`:
```ts
function handlePress() {
  if (syncStatus === 'failed') { onFailedPress?.(); return; }
  if (onPress) { onPress(); return; }      // selection mode is active
  onDetailPress?.();                        // default: open detail
}
```

### Known constraints and edge cases

- **`react-native-share` requires a prebuild for a standalone build.** In Expo Go, `Share.shareSingle` may not be available depending on the Expo Go version. If it throws `Invariant Violation: TurboModuleRegistry`, wrap the call in a try/catch and show an alert: *"Sharing is not available in Expo Go — build a development client to use this feature."*
- **Facebook App ID on iOS:** `appId` is required by the Instagram SDK on iOS. Without it, the share call silently fails. Ensure `EXPO_PUBLIC_FB_APP_ID` is set before testing on a real iOS device.
- **Local URI must be `file://`:** `react-native-share` does not accept `http://` or `https://` URLs for `backgroundImage`. Always pass the result of `resolvePhotoUri` (which returns a local path) or `downloadPhotoToCache`.
- **Android scoped storage:** On Android 10+, the `file://` URI must be a path within the app's cache or files directory (already satisfied by `downloadPhotoToCache` which writes to `cacheDirectory`).
